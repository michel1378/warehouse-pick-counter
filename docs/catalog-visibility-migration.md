# Независимая видимость карточек

Перед публикацией кода выполнить в SQL Editor рабочей базы:
`supabase/migrations/20261103064143_independent_catalog_visibility.sql`.
Доступный через MCP проект не содержит `public.size_products`; миграция туда не применялась.

Миграция добавляет `show_in_availability` и `show_in_sizes`. Все существующие
карточки остаются в наличии с прежним `active`. В размерах первоначально
включаются карточки с сохранёнными примерами. Другие поля не меняются.
Повторное выполнение не сбрасывает настройки. Для новых карточек значения
задаёт сервер в зависимости от раздела создания.

В админке каждого раздела переключатель «Скрытые» открывает карточки,
выключенные в этом разделе, включая выключенные в обоих. Изменение галочек
сохраняет общую запись и повышает revision. Сотрудники не могут менять настройки;
прямой доступ к таблице для anon/authenticated закрыт. Подбор для сотрудника
требует active, show_in_sizes, фото, размеры и примеры.

Локальная проверка: `npm.cmd run typecheck`, `npm.cmd run build`,
`node tests/availability-create.cjs`, `node tests/availability.cjs`,
`node tests/size-photos.cjs`, `node tests/sizes.cjs`, `node tests/size-methods.cjs`.
SQL-тесты проверяют сохранность старых строк, первоначальное распределение,
повторное выполнение, создание из обоих разделов, четыре сочетания галочек,
повторное чтение, восстановление скрытых карточек и серверный отказ сотрудникам.

После подтверждения выполнения SQL: обычный git push, затем проверка
публикации и smoke-проверка разделов на рабочем сайте.
