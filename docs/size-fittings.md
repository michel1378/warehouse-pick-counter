# Реальные примерки в карточке товара

В «Размеры → Редактировать» появился блок «Реальные примерки».

1. Раскрыть «Три человека: рост, вес и мерки тела». Сохранить каждый профиль
   собственной кнопкой. UUID и номер 1–3 постоянны и общие для всех вещей.
2. Нажать «Добавить примерку». Выбрать человека, бирку, цвет (если цвета
   разделены), фактическую посадку по объёму, длину вещи и рукав. Для брюк
   рукав не запрашивается. При необходимости оставить заметку.
3. Добавить столько размеров на каждого человека, сколько действительно
   примерили. Сохранить карточку кнопкой «Сохранить вещь».
4. Повторить с другой вещью: люди уже доступны, повторно заполнять их не нужно.

Плечи профиля — ширина тела, грудь/талия — полный обхват тела. Это не ширина
груди одежды и не полупояс. Мерки тела не подставляются в поля любимой вещи.
На момент примерки сервер записывает снимок мерок. Последующие изменения
профиля не переписывают старую историю. Если исправляется именно ошибочный
снимок, использовать «Взять текущие мерки человека», затем сохранить вещь.

## Как влияет на подбор

Удачная примерка (одна из трёх посадок, нормальная длина и рукав) становится
живым ориентиром для модели, цвета, роста/веса и посадки. В точном совпадении
она приоритетнее прежнего предположения; для соседних параметров участвует
в общем расчёте. Повтор одной примерки не создаёт дополнительного веса.
Данные поступают из каталога после сохранения, новая публикация кода не нужна.

Тесный/слишком большой размер, короткая/лишняя длина не становятся удачным
ориентиром. На близких параметрах тот же неудачный размер не подтверждается
автоматически. Если у людей с одинаковыми ростом и весом подходят разные
размеры, в том числе при разном обхвате груди, программа не усредняет их:
нужны мерки подходящей вещи. Три человека не доказывают точность для всех фигур.
Новый цвет можно начать калибровать собственными примерками; чужой цвет
автоматически не используется. Любимая вещь по-прежнему сравнивается с сеткой.

## Хранение и доступ

- `size_fit_people`: ровно три слота, UUID генерируются базой, рост/вес сначала
  пусты. Никакие настоящие или выдуманные мерки миграция не добавляет.
- `size_products.fittings`: JSON-массив наблюдений со снимками тела и датой.
- `/api/size-fit-people`: чтение и изменение только для администратора.
- `/api/sizes`: примерки сохраняются вместе с карточкой под её revision.
  В старом запросе без поля fittings существующие примерки не стираются.
- Изменения требуют корректного Origin и актуальной версии; запросы ограничены
  по размеру. Снимки тела и даты генерируются сервером, из клиента не принимаются.
- Профили закрыты RLS и не доступны через anon/authenticated. Данные людей
  не коммитятся и не отправляются во внешнюю модель. Расчёт выполняется на сайте.

## Проверено

`node tests/size-fittings.cjs`: профиль → сохранение примерки → повторное
чтение каталога → реальное изменение рекомендации; неизменность прошлых
снимков, явное обновление, разделение цветов, отрицательные примерки,
различия фигур, права доступа, Origin и конфликт версии.
Миграция отдельно проверена в PostgreSQL-совместимом PGlite: три пустых
профиля, уникальные слоты, ограничения и права. В рабочей базе проверены
наличие трёх профилей и закрытый доступ. Фиктивные примерки туда не записывались.
Прошлые тесты размерного подбора и сборка также выполняются.
