# Раздел «Наличие»

Раздел использует товары, названия, размерные ряды, видимость и галереи из `size_products`. Дублирующий каталог не создаётся. Примеры и алгоритм подбора размеров, заказы и scanner-agent не изменены.

## Запуск

1. В SQL Editor существующего проекта Supabase выполните `supabase/migrations/20261102_availability.sql`. Предполагается, что каталог размеров (`20261004_size_catalog.sql`) уже установлен. Миграция добавляет поля, не переписывает прежние данные и допускает повторное выполнение. Удалённая БД в рамках реализации не изменялась.
2. Используйте текущие `.env.local` и способ запуска сайта: `npm run build`, затем `npm start` (или `npm run dev` для разработки). Новые переменные и зависимости не нужны.
3. Администратор: `/admin/availability`; сотрудники: `/availability`. Пункт «Наличие» добавлен в навигацию. Сотрудникам доступны только активные товары; скрытые товары доступны администратору.
4. Администратор раскрывает товар и нажимает «Редактировать наличие»: вводит состав, материал, растяжимость, цвета и выбирает размеры из существующего размерного ряда. Название, базовая галерея и размерный ряд редактируются в прежнем разделе «Размеры».

Незаполненные сведения показываются как «Не указано». По цвету `sizes: null` означает «Не указано», пустой список — «Нет доступных размеров». Количеств и автоматического списания нет. Фото размерной сетки и фото на модели загружаются отдельно; без новой загрузки они сохраняются. Новая загрузка заменяет только соответствующую дополнительную группу, а не прежнюю галерею. Фотографии сжимаются прежним обработчиком в JPEG до 1000 пикселей и 400000 символов; до шести фото на модели и одна сетка на товар. Сетка и другие изображения открываются в диалоге с увеличением и прокруткой; Esc закрывает диалог.

Сессии и повторная проверка активного сотрудника используют существующий `getSession`. API запрещает изменения сотрудникам и запросы записи с чужого Origin, проверяет размеры и изображения, ограничивает тело запроса, проверяет revision. Изменение в другом окне возвращает конфликт без перезаписи. Полный каталог не содержит изображений: они выдаются по одному через защищённые маршруты. Прямой доступ anon/authenticated к таблице остаётся запрещён; service-role ключ остаётся на сервере.

## Проверка

`npm run typecheck`, `npm run build`, `node tests/availability.cjs`, `node tests/sizes.cjs`, `node tests/size-photos.cjs`, `node tests/size-methods.cjs`, `node tests/employee-session.cjs`.

Тесты наличия проверяют маршруты с изолированной сессией и БД, а миграцию — в локальном PostgreSQL-совместимом PGlite: сохранность существующих данных, повторное применение, запрет прямого доступа. Перед рабочим использованием после применения миграции проверьте реальные входы администратора и сотрудника в браузере, загрузку изображений и чтение сохранённых данных. Публикация не выполнялась.
