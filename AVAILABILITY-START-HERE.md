# Раздел «Наличие»

Раздел использует товары, названия, размерные ряды, видимость и галереи из `size_products`. Дублирующий каталог не создаётся. Примеры и алгоритм подбора размеров, заказы и scanner-agent не изменены.

## Запуск

1. В SQL Editor существующего проекта Supabase выполните `supabase/migrations/20261102_availability.sql`. Предполагается, что каталог размеров (`20261004_size_catalog.sql`) уже установлен. Миграция добавляет поля, не переписывает прежние данные и допускает повторное выполнение. Удалённая БД в рамках реализации не изменялась.
2. Используйте текущие `.env.local` и способ запуска сайта: `npm run build`, затем `npm start` (или `npm run dev` для разработки). Новые переменные и зависимости не нужны.
3. Администратор: `/admin/availability`; сотрудники: `/availability`. Пункт «Наличие» добавлен в навигацию. Сотрудникам доступны только активные товары; скрытые товары доступны администратору.
4. Администратор раскрывает товар и нажимает «Редактировать»: меняет название, галерею, сетку, фото на модели, состав, материал, растяжимость, цвета и доступные размеры. Для создания используется кнопка «Добавить позицию» и та же форма. Примеры подбора редактируются в прежнем разделе «Размеры».

Незаполненные сведения показываются как «Не указано». По цвету `sizes: null` означает «Не указано», пустой список — «Нет доступных размеров». Количеств и автоматического списания нет. Кнопка «Редактировать» в каждой карточке администратора открывает общую форму создания/редактирования, загружая свежие данные с сервера. Все существующие фото товара, сетка и фото на модели видны в форме. В каждой галерее можно добавлять фото, заменять и удалять отдельные изображения, менять порядок стрелками. Для сетки доступны отдельные загрузка/замена и удаление. Фотографии сжимаются прежним обработчиком в JPEG до 1000 пикселей и 400000 символов. Сетка и другие изображения открываются в диалоге с увеличением и прокруткой; Esc закрывает диалог.

Сохранение редактирует ту же запись по `id` и `revision`; `examples`, `note` и `active` не передаются в обновление. Нетронутые группы фото также не передаются. Изменённая галерея отправляет новые JPEG и ссылки `{index}` на оставляемые фото; сервер разрешает эти ссылки только из той же позиции с проверенной версией. Это позволяет добавлять/переставлять фото без повторной загрузки старых файлов. Первое фото синхронно записывается в `photo`, вся галерея — в `photos`, счётчик — в `photo_count`, поэтому общий маршрут фото и раздел подбора размеров видят ту же галерею. Поддерживается старый формат с единственным `photo` и пустым `photos`. Страница редактора `/api/availability/[id]` доступна только администратору; изображения по прежним маршрутам доступны сотрудникам для активных товаров.

Сессии и повторная проверка активного сотрудника используют существующий `getSession`. API запрещает изменения сотрудникам и запросы записи с чужого Origin, проверяет размеры и изображения, ограничивает тело запроса, проверяет revision. Изменение в другом окне возвращает конфликт без перезаписи. Полный каталог не содержит изображений: они выдаются по одному через защищённые маршруты. Прямой доступ anon/authenticated к таблице остаётся запрещён; service-role ключ остаётся на сервере.

## Проверка

### Создание позиций

Для кнопки «Добавить позицию» требуется дополнительная миграция `supabase/migrations/20261102_availability_create.sql` после основной миграции наличия. Она только расширяет допустимые ограничения размеров и количества фото до нуля, не меняет строки или примеры. Название обязательно; остальные поля можно заполнить позже в редакторе наличия. Новая позиция записывается один раз в `size_products`, доступна сотрудникам в наличии и не попадает в подбор до заполнения размеров, фотографии и примеров. Примеры заполняются в административном разделе «Размеры». Удаление размера, используемого в примерах, через наличие запрещено; сами примеры не изменяются. Скрытие товара в разделе «Размеры» по-прежнему скрывает его и в наличии.

Суммарный предел одного запроса наличия — 4,3 МБ; группы можно загружать последовательно. На товар можно сохранить до шести фото товара, одну сетку и шесть фото на модели. Старые изображения без новой загрузки сохраняются. Создание возвращает 201 и сохранённую карточку; повторный GET читает её из той же таблицы. Тест создания и последующего чтения: `node tests/availability-create.cjs`.

`npm run typecheck`, `npm run build`, `node tests/availability.cjs`, `node tests/sizes.cjs`, `node tests/size-photos.cjs`, `node tests/size-methods.cjs`, `node tests/employee-session.cjs`.

Тесты наличия проверяют маршруты с изолированной сессией и БД, а миграцию — в локальном PostgreSQL-совместимом PGlite: сохранность существующих данных, повторное применение, запрет прямого доступа. Перед рабочим использованием после применения миграции проверьте реальные входы администратора и сотрудника в браузере, загрузку изображений и чтение сохранённых данных. Публикация не выполнялась.
