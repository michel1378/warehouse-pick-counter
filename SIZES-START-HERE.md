# Раздел «Размеры» — установка

Архив содержит исходники вашего сайта с новым разделом. Сам сайт в Vercel и ваша рабочая база этим архивом ещё не изменены.

## 1. Обновить файлы на компьютере

1. Сохраните резервную копию рабочей папки проекта.
2. Распакуйте этот ZIP в отдельную папку.
3. Скопируйте его содержимое в существующую папку `warehouse-pick-counter`. Разрешите объединение папок и замену совпадающих файлов. Не удаляйте старую папку проекта целиком.
4. Ваши `.env.local`, `.git`, файлы сканера и остальные отсутствующие в архиве файлы должны остаться на месте. В этом архиве секретов и настроек доступа нет.

Если после отправки исходного архива вы уже изменяли эти же файлы сайта, сначала сравните изменения, чтобы не затереть свежие правки.

## 2. Создать таблицу в существующем проекте Supabase

1. В VS Code откройте `supabase/migrations/20261004_size_catalog.sql`.
2. Скопируйте всё содержимое.
3. В Supabase откройте проект этого сайта → SQL Editor → новый запрос.
4. Вставьте SQL и выполните Run. Ожидается успешное выполнение без ошибок.

Выполняйте только эту новую миграцию. Она создаёт отдельную таблицу `size_products`, включает RLS и оставляет доступ к таблице только серверной роли. Повторный запуск допустим. Таблицы сканов, выплат, смен и сотрудников она не меняет. Бакет Storage и новые API-ключи не нужны.

## 3. Проверить и опубликовать обычным способом GitHub → Vercel

В терминале VS Code, открытом в папке проекта:

```sh
npm run typecheck
node tests/sizes.cjs
npm run build
```

Зависимости не изменялись. Если они ещё не установлены, предварительно выполните `npm ci`.

Затем отправьте изменения в GitHub тем же способом и в ту же ветку, из которой публикуется действующий сайт. В Vercel дождитесь Ready именно у нового коммита. Не создавайте новый проект и не переносите сайт на другой хостинг.

Обновлять ScannerAgent.exe для этого раздела не нужно.

## 4. Заполнить первую вещь

Вход администратора → «Размеры» → «Добавить вещь»:

- Загрузите фотографию (JPEG/PNG/WebP; браузер уменьшит её автоматически).
- Введите название и подпись: «Не маломерит», «Маломерит на размер» или свой текст.
- Укажите размеры на бирке от меньшего к большему, например `M, L, XL, 2XL`. Это размерный ряд модели, не учёт остатков.
- Внесите 10–20 ваших примеров: рост, вес, посадка, размер на бирке.
- Посадки: «В обтяг», «Размер в размер», «Немного оверсайз».
- В «Проверить подбор перед сохранением» попробуйте несколько новых сочетаний роста/веса, для которых вы заранее знаете свой ответ.
- Нажмите «Сохранить вещь».

Можно вставить сразу четыре колонки из Excel. Для обычного текста используйте точку с запятой. Например, формат строки: `рост;вес;Размер в размер;размер на бирке` (подставьте настоящие значения). Числа в этом руководстве не являются рекомендациями для реальных вещей.

Чтобы скрыть модель, снимите «Показывать сотрудникам» и сохраните. Все введённые рекомендации сохранятся. Повторное включение вернёт вещь в каталог.

## 5. Сотрудникам

После обычного входа по PIN нажать «Размеры» или открыть `/sizes` на том же сайте. Ссылки добавлены на страницы сборки, отметок и отзывов. Раздел доступен всем активным сотрудникам с действующей сессией; редактировать может только администратор.

Фото → крупное название → небольшая подпись. Нажатие на карточку раскрывает поля внутри неё. Рост и вес вводятся для выбранной вещи; общих полей на весь каталог нет. По умолчанию посадка «Размер в размер». Результат появляется автоматически, без кнопки и без обращения к нейросети. «Новый клиент» очищает поля и сбрасывает посадку.

На новых компьютерах достаточно закрепить вкладку `/sizes` и войти как обычно. База единая. Изменения загружаются при открытии/возвращении к вкладке; есть кнопка «Обновить». Ошибка обновления блокирует старые рекомендации до успешной загрузки.

## Как подбирается размер

Подбор использует только примеры выбранной вещи и выбранной посадки. Он не ограничен точными совпадениями:

1. Точный пример даёт сохранённый размер на бирке.
2. Для новых параметров выбираются ближайшие примеры по расстоянию `sqrt(((рост−рост_примера)/7)^2 + ((вес−вес_примера)/10)^2)`.
3. Нужны хотя бы два близких примера. Близость ограничена 10 см, 15 кг и расстоянием 1.8; выход за общий диапазон допускается только на 3 см / 4 кг.
4. У трёх ближайших (включая все равноудалённые) взвешиваются голоса за размер. Вес — `1/(расстояние²+0.08)`. При доле меньше 0.75 или противоречии почти одинаково близких примеров результат — «Нужно уточнение».
5. Нет примеров нужной посадки, параметры далеко от известных или близкие размеры спорят — система просит уточнить. Она не выбирает наугад крайний размер из размерного ряда.

Это прозрачная начальная эвристика, а не обученная нейросеть и не доказанная точность 75%. Масштабы и пороги нужно проверить на ваших реальных примерах. Веса голосов не являются вероятностью правильной посадки. 10–20 строк — старт, а не гарантия точности. Желательно проверить минимум 5 дополнительных случаев, которые не входят в таблицу, для каждой важной модели.

Пометка о маломерности — справочный текст: размер не увеличивается второй раз. Нет автоматического правила «оверсайз +1»: нужны ваши примеры соответствующей посадки. Размеры за пределами указанного ряда не выдаются; недоступный размер не заменяется произвольным имеющимся.

## Что проверено при подготовке

- `npm run typecheck` и производственная сборка `npm run build`.
- 22 автоматические проверки: точные/новые параметры, посадки, спорные случаи, выход за диапазон, вставка таблицы, валидация, повторная миграция, права таблицы и конфликт версий.
- API-проверки с тестовой базой прошли: запрет записи сотруднику, запрет запросов с другого сайта, валидация, фото, создание, конфликт двух редакторов, скрытие/возврат вещи, ограничение размера запроса, загрузка обеих страниц. Это не проверка вашего рабочего Supabase.
- Рабочий Supabase, Vercel и реальные рекомендации владельцев здесь недоступны. Внешний вид в браузере не проверен: запуск тестового браузера в среде оказался недоступен.
